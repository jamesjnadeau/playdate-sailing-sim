# Dithered Foam and Trailing-Off Wake Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draw all the boat's water foam (hull ring, bow wave, wake) as dithered white stipple instead of 1px white lines, and make each wake line split in the middle past a configurable distance astern, then shrink from both ends until it disappears.

**Architecture:** The wake line geometry (where a line splits and how its two halves shrink) is a pure function in a new `src/sim/wake.c`, so it is unit-tested on the host. `src/pd/render.c` `draw_waterline` is rewritten to fill thin polygons with a *foam pattern*: the existing 17-level dither from `render_pattern` with a mask, so only the white pixels draw and the sea shows through the gaps. The trail-off distance is a per-boat `look.wake_fade_m` with a default, so boat files that omit it are unchanged.

**Tech Stack:** C99, `-Wall -Wextra -Werror` with ASan/UBSan, host tests via `make -C tests test` using `tests/t.h` (`T_ASSERT`, `T_NEAR`, `T_RUN`), Playdate C API (`fillPolygon` with `LCDPattern`).

**Spec:** No spec doc. Requirements come from this session. The user wants:
- all the foam dithered instead of white lines, not only the wake;
- the behind-the-boat lines to trail off from the middle after a configurable distance, so they read as two separate lines, with each end shrinking until it vanishes behind the boat;
- the existing wake motion kept.

Assumptions made in the conversation and not objected to:
- the trail-off distance is the value at full speed (4 m/s and up), and the wake length scales with speed (`3 + 6k` m);
- the foam shade must stay lighter than the sea behind it (checked by eye, Task 3);
- the setting lives in each boat's JSON, which I recommended and the user did not contradict.

## Review Focus

Failure modes the spec implies that no feature test would otherwise cover:

1. `wake_fade_m` at or above the full-speed wake length (9 m): lines never split. Pinned in Task 1.
2. `wake_fade_m` of 0: lines split from the transom with no crash or divide-by-zero. Pinned in Task 1.
3. A line at exactly `f = 1` (the far end) must report "not visible", not a zero-length or inverted segment. Pinned in Task 1.
4. A foam polygon with any vertex behind the camera is skipped whole, never drawn with a stale or garbage vertex. Pinned by the frame check in Task 3.
5. Heel hides one hull side: its foam ring is skipped, as the line version does today. Pinned by the frame check in Task 3.

### Task 1: Wake line geometry

**Files:**
- Create: `src/sim/wake.h`, `src/sim/wake.c`
- Test: `tests/test_wake.c`

**Interfaces:**
- Produces (all in `wake.h`):
  - `float wake_length(float k)`: metres astern of the transom the wake reaches, `3 + 6k`, with `k` clamped to `[0, 1]`.
  - `float wake_fade_start(float fade_m)`: fraction of the wake length at which lines start to split, `max(0, fade_m / wake_length(1))`. Not clamped above, so a value `>= 1` means "never splits".
  - `bool wake_segment(float f, float fade_start, float half, float *lo, float *hi)`: for the line at fraction `f` (0 at the transom, 1 at the far end) whose full half-width is `half` m, gives the lateral extent of each of the two segments, `*lo` to `*hi` measured outward from the track centre (the other segment is the mirror image). Returns false when the segment has shrunk away.

- [ ] **Step 1: Write the failing tests** in `tests/test_wake.c` (model the file on `tests/test_hullgeom.c`: `#include "t.h"`, `T_RUN` list in `main`, `return T_DONE()`):
  - `test_wake_length_follows_speed`: `wake_length(0)` is 3, `wake_length(1)` is 9, `wake_length(0.5)` is 6, and `wake_length(-1)` / `wake_length(5)` clamp to 3 / 9 (`T_NEAR`).
  - `test_fade_start_is_a_fraction_of_the_full_speed_wake`: `wake_fade_start(4.5)` is 0.5, `wake_fade_start(0)` is 0, `wake_fade_start(20) >= 1`.
  - `test_line_is_whole_before_it_starts_to_split`: for `f` in `{0, 0.25, 0.5}` with `fade_start = 0.5` and `half = 2`: returns true, `lo == 0`, `hi == 2` (`T_NEAR`, 1e-6).
  - `test_line_splits_then_shrinks_from_both_ends`: `fade_start = 0.5`, `half = 2`, `f = 0.75` (so `t = 0.5`): returns true, `lo` is 0.5 and `hi` is 1.5 (`lo = 0.5*t*half`, `hi = half*(1 - 0.5*t)`). Then sweeping `f` from 0.5 to 0.95 in steps of 0.05, `lo` never decreases, `hi` never increases and `hi - lo` never increases.
  - `test_line_has_vanished_at_the_far_end`: `wake_segment(1.0, 0.5, 2, ...)` returns false; so does `f = 0.99`. This pins Review Focus 3.
  - `test_never_splits_when_fade_is_beyond_the_wake`: for `f` in `{0, 0.5, 1.0}` and `fade_start = wake_fade_start(20)`: returns true with `lo == 0`, `hi == half`. This pins Review Focus 1.
  - `test_zero_fade_splits_from_the_transom`: `fade_start = wake_fade_start(0)`: at `f = 0` the line is whole, at `f = 0.5` `lo > 0` and `hi < half`, and every output is finite. This pins Review Focus 2.

Expected: compile failure, `wake.h: No such file`.

In `wake_segment`, `t = (f - fade_start) / (1 - fade_start)` clamped to `[0, 1]`, used only when `f > fade_start`, so a `fade_start >= 1` never divides by zero. Then `*lo = 0.5*t*half`, `*hi = half*(1 - 0.5*t)`, and return `t < 0.98f`. Include `<stdbool.h>`, follow the header-guard and comment style of `hullgeom.h`.

### Task 3: Dithered foam in the renderer

**Files:**
- Modify: `src/pd/render.c` (add near `render_pattern`, around line 43; rewrite `draw_waterline`, line 636)

**Interfaces:**
- Consumes: `wake_length`, `wake_fade_start`, `wake_segment` (Task 1, `#include "wake.h"`), `g->boat.look.wake_fade_m` (Task 2).
- Produces (file-local to `render.c`):
  - `static LCDColor foam_pattern(int level)`: the same dither as `render_pattern(level)` but with the mask set to the colour bits, so black pixels are transparent. Level 0 is solid white and higher is sparser. Clamp to `[0, LEVELS-2]` like `render_pattern`. Build lazily into a second table `foam_pats[LEVELS]` filled from `pats[l][y]` with `foam_pats[l][8+y] = pats[l][y]`, then use it.
  - `static void foam_poly4(PlaydateAPI *pd, const int p[8], int level)`: `fillPolygon(4, ...)` with `foam_pattern(level)`.

This task has no host unit test, since `render.c` is outside `tests/`. Its checks are the build and the frame review in steps 4 to 5.

- [ ] **Step 1: Add `foam_pattern` and `foam_poly4`** as specified above. Keep `render_pattern` untouched.

- [ ] **Step 2: Rewrite `draw_waterline`** keeping its signature, its early-outs (`hidden` side skipped, `sp < 0.5f` returns after the hull ring and transom) and its `k`, `frame` and `phase` definitions. Replace every `drawLine` with a dithered quad. A quad is skipped whole if any of its four corners fails to project:
  - **Hull ring:** for each side and each pair of neighbouring stations `i, i+1` (`N = 9`), the quad runs between the inner ring (`side_wl` with `wscale 1.0`) and the outer ring (`wscale 1.08 + 0.2*bury + 0.1*k`), both through `boat_pt(&hk, ...)`. Level `1 + (int)((1 - bury) * 3)`, so the buried leeward side is denser.
  - **Transom foam:** one quad between the two transom `side_wl(..., 1.0f, ...)` points and the same points moved 0.3 m aft (`x - 0.3f` before `boat_pt`), level 2. Only when `hidden == 0`, as now.
  - **Bow wave:** each crest becomes a ribbon. For each segment between stations `f_i, f_{i+1}` along the existing crest points, the quad's other two corners sit `w = (0.10f + 0.30f*k) * (1 - 0.5f*f)` m further out laterally (`water_pt`). Level `1 + (int)(f * 7)`. Keep the existing `jig` jitter on the crest line.
  - **Wake:** keep the existing ring loop: `phase`, `f`, `back`, `half` and the `frand(...) < f*0.6` dropout. Replace the cross-line with `wake_segment(f, wake_fade_start(g->boat.look.wake_fade_m), half, &lo, &hi)`, skipping the ring when it returns false. For each side (`s = -1, +1`) draw a quad with corners `(back, s*lo)`, `(back, s*hi)`, `(back - depth, s*hi)`, `(back - depth, s*lo)` through `water_pt`, with `depth = 0.25f + 0.35f*k` and level `2 + (int)(f * 10)`, capped at 14. Replace the literal `3.0f + 6.0f * k` with `wake_length(k)`.
  - The level numbers and `depth`/`w` constants above are starting values to tune by eye in step 5. They are my call, not the user's.
