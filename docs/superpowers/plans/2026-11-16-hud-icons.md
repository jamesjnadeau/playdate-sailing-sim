# HUD Heading/Heel Icons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show boat speed, heading (icon), heel (icon), wind speed, wind dial, AP and AT in a right-justified cluster in every mode, so TRIM/HOIST no longer hide them.

**Architecture:** Cluster positions come from a pure function in `src/sim/hudinfo.c` (host-testable, takes measured text widths). `src/pd/hud.c` measures text, calls it, and draws icons with graphics primitives. The web build drops the `nav` flag and mirrors the same order in DOM/CSS.

**Tech Stack:** C (Playdate SDK, host test harness in `tests/`, `harness/`), web JS (`web/www/js/ui/hud.js`, `web/src/web_json.c`).

**Spec:** `docs/superpowers/specs/2026-11-16-hud-icons-design.md`

## Global Constraints

- Playdate 400x240, 1-bit; bar rows 220..239 (`HUD_H` = 20); mode cell x 0..53 is unchanged.
- Wind dial unchanged: centre x 388, radius 8 (x 380..396).
- Cluster right to left: dial, wind speed (right edge x 376), heel, heading, boat speed, then AP, then AT; 1 px separators.
- Heading icon: glyph ➢ rotated to point up, ~11x11 px, left half filled, right half outlined. Heel icon: glyph ∢, horizontal base, second leg fixed at 30 degrees, small arc, ~12x12 px. The heel icon does not track the real heel.
- Nothing is hidden by mode. `hud_shows_nav()` is removed.
- Trim/hoist bar: 64 px wide (was 74), starting at x 100 (was 108).
- Positions are computed from measured text widths at run time, not hard-coded from the mockup (mockup values: speed x 234..270, heading 279..313, heel 322..355, wind 364..376, worst-case left edge x 173).

## Review Focus

- Heel text `-14`/`-9`/`+0` is wider or narrower than `+14`: cluster stays right-aligned, nothing overlaps.
- Heading `000` and `359` and an AP target of `000`: always 3 digits, width stable.
- Wind speed of 3 digits (storm, e.g. `100`): grows leftwards, does not touch the dial.
- Sail name of 8 widest characters (`%.8s`) must not run into the trim bar, and the bar must keep a usable width with AP and AT on.
- Camera mode with the vertical arrow: mode-cell arrow still draws, cluster still shown.

### Task 1: Cluster layout helpers

**Files:**
- Modify: `src/sim/hudinfo.h`, `src/sim/hudinfo.c`
- Test: `tests/test_hudinfo.c`

**Interfaces:**
- Produces:
  ```c
  #define HUD_DIAL_CX 388
  #define HUD_ICON_HDG_W 11
  #define HUD_ICON_HEEL_W 12
  typedef struct {
      int aws_x;                       /* left of the wind-speed text */
      int heel_x, heel_icon_x;         /* left of the heel text / icon */
      int hdg_x, hdg_icon_x;           /* left of the heading text / icon */
      int speed_x;                     /* left of the boat-speed text */
      int ap_x, ap_icon_x;             /* -1 when AP is off */
      int at_icon_x;                   /* -1 when AT is off */
      int sep[5]; int nsep;            /* x of each 1 px separator */
      int left;                        /* leftmost pixel used by the cluster */
  } HudCluster;
  HudCluster hud_cluster_layout(int w_aws, int w_heel, int w_hdg, int w_speed, int w_ap, bool at, bool ap);
  void hud_sail_bar_span(int name_w, int left, int *x, int *w);   /* bar start and width */
  ```
